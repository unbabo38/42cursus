# NetPractice
*This project has been created as part of the 42 curriculum by [tmura].*


## Description
このプロジェクトは、ネットワークの基礎（IPアドレッシング、ルーティング、サブネット計算）を実践的に学ぶための課題です。
全10レベルのパズルを解きながら、端末から外部ネットワークへ通信を届けるための論理的な経路設計を習得しました。
また、レベル6-10のうちからランダムで提出される３問を１５分以内に解けるように繰り返し練習しました。

特に、端末側での「デフォルトゲートウェイ」の設定がいかに重要であるか、そしてルーターがどのようにパケットを中継するかを実機に近いシミュレーションを通じて学習しました。


## Instructions
- トレーニングインターフェースの実行
リポジトリのルートディレクトリで以下のスクリプトを実行します
```bash
./run.sh
```
起動後、ブラウザで通常は http://localhost:8080にアクセスします。

- 設定の書き出し (Export)
各レベルをクリアし、すべての通信テスト（緑色）に合格したら、画面上の 「Get my config」 ボタンを押して設定を書き出します。

- 提出要件 (Submission Requirements)
合計10個のエクスポートされた設定ファイルを、リポジトリのルートディレクトリに配置。


## Resources
学習したネットワーク概念
本プロジェクトを通じて、以下の技術要素について学びました：

- OSI参照モデル:
OSI参照モデルは、ネットワーク通信を7つの階層（L1〜L7）に分けて整理した概念モデルである。
各レイヤーは役割が明確に分離され、設計・実装・トラブルシュートを体系的に行える。
通信障害の原因を「どの層の問題か」で切り分けられることが最大の利点である。

- TCP/IPアドレッシング: IPv4の構造と、クラスレスなネットワーク設計。
IPアドレスで機器とネットワークを識別する仕組み
IPv4アドレスの構造
IPv4は 32ビット：
11000000.10101000.00000001.00001010　= 8bit × 4 = オクテット
[ ネットワーク部 ] [ ホスト部 ]に分かれる

IPv4は32bitで構成され、ネットワーク部とホスト部に分かれる。
CIDR（クラスレス設計）は`/xx`で境界を指定し、クラスに依存せず柔軟にネットワークサイズを定義できる。
これによりIPアドレスの節約と効率的なルーティング集約が可能になる。

- サブネットマスク:
CIDR表記（/24 等）を用いたネットワーク分割と、ブロードキャストアドレス・ネットワークアドレスを除いた「有効なホスト範囲」の計算。
IPv4アドレスのどこまでがネットワーク部でどこからがホスト部かを示すビット列である。
`255.255.255.0` や `/24` のように表現され、1がネットワーク部、0がホスト部を意味する。
CIDRと組み合わせることで、ネットワークを柔軟に分割・設計できる。

- デフォルトゲートウェイ
デフォルトゲートウェイは、宛先が同一ネットワーク外の場合にパケットを最初に送るルーターのIPアドレス。
端末はルーティングテーブルに一致する経路がないとき、デフォルトゲートウェイに通信を委ねる。
これによりローカルネットワークからインターネットなど外部ネットワークへ到達できる。

- ルーターとスイッチ:
パケットの宛先IPを見て次のホップ（ネクストホップ）を決定するルーターの仕組み。
スイッチはMACアドレスを基に、同一ネットワーク内の機器同士の通信を中継する（レイヤー2）。
ルーターはIPアドレスを基に、異なるネットワーク間の通信経路を判断して転送する（レイヤー3）。
つまりスイッチは「LAN内の配送係」、ルーターは「ネットワーク間の案内役」である。

- AIの活用について (AI Usage)
各種用語の確認、ネットワーク範囲の確認など
