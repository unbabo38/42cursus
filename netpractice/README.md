NetPractice
This project has been created as part of the 42 curriculum by [tmura].

Description
このプロジェクトは、ネットワークの基礎（IPアドレッシング、ルーティング、サブネット計算）を実践的に学ぶための課題です。全10レベルのパズルを解きながら、端末から外部ネットワークへ通信を届けるための論理的な経路設計を習得しました。

特に、端末側での「デフォルトゲートウェイ」の設定がいかに重要であるか、そしてルーターがどのようにパケットを中継するかを実機に近いシミュレーションを通じて学習しました。

Instructions
トレーニングインターフェースの実行
リポジトリのルートディレクトリで以下のスクリプトを実行します：

Bash
./run.sh
起動後、ブラウザで指定されたURL（通常は http://localhost:8080）にアクセスしてください。

設定の書き出し (Export)
各レベルをクリアし、すべての通信テスト（緑色）に合格したら、画面上の 「Export」 ボタンを押して設定を書き出します。

提出要件 (Submission Requirements)
合計10個のエクスポートされた設定ファイルを、リポジトリのルートディレクトリに配置してください。

ファイルが欠けていたり、ディレクトリ構造が異なると評価の対象外となるため注意してください。

Resources
学習したネットワーク概念
本プロジェクトを通じて、以下の技術要素を深く理解しました：

OSI参照モデル: レイヤー2（MACアドレス/スイッチ）とレイヤー3（IPアドレス/ルーター）の役割の違い。

TCP/IPアドレッシング: IPv4の構造と、クラスレスなネットワーク設計。

サブネットマスク: CIDR表記（/24 等）を用いたネットワーク分割と、ブロードキャストアドレス・ネットワークアドレスを除いた「有効なホスト範囲」の計算。

デフォルトルート (default): 端末のルーティングテーブルにおいて、特定の宛先が不明なパケットを「外の世界」へ送り出すための、0.0.0.0/0 と同等の役割を持つラストリゾート（最後の手段）設定。

ルーターとスイッチ: パケットの宛先IPを見て次のホップ（ネクストホップ）を決定するルーターの仕組み。

AIの活用について (AI Usage)
タスク: ルーティングテーブルにおける「宛先(Destination)」と「送信元(Source)」の定義の違いを整理するために使用。

箇所: 端末側テーブルでなぜ自分のIPではなく default を指定すべきかの論理構築。

方法: 自身が導き出したサブネットの計算結果（有効なホスト数）のクロスチェック。
